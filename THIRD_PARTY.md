## Fetched at build time, not vendored

Three directories are fetched on demand and **all three are gitignored**. None
of them is part of this repository, and each keeps its own licence.

### `third_party/rockbox` — the WMA decoder, LGPL 2.1-or-later

Every audio payload on the disc is WMAv2 standard (0x0161) — all 885 of them,
measured from their own ASF headers. Rockbox's `libwma` decodes exactly that,
in fixed point, with no allocator and no build system of its own, which is what
lets the same six files serve the desktop binary, the Android `.so` and the
wasm module.

`tools/fetch_wma.sh` fetches them, pinned by commit **and** by sha256
(`tools/fetch_wma.sha256`, checked on every fetch). `libwma` is a fixed-point
derivative of FFmpeg's `wmadec` and carries FFmpeg's **LGPL 2.1-or-later**, as
do the MDCT / FFT / bitstream helpers taken with it. Each file keeps its own
header; **nothing is relicensed and nothing is modified** — the adaptation
lives entirely in `tools/cextract/wma/`, which is this project's own code under
the MIT licence.

LGPL compliance for a source-distributed project that links these files
unmodified is satisfied by keeping them **separable and attributed**, which is
precisely why they are fetched rather than copied into this history.

**Without the fetch the build still works.** `b3_wma_stub.c` has the same API
and reports "no WMA decoder"; the two music stages are compiled and linked
either way, so you get a working game with silent music rather than a build
failure.

```sh
sh tools/fetch_wma.sh            # -> third_party/rockbox/
sh tools/fetch_wma.sh --check    # verify what is there, fetch nothing
```

### `android/third_party` — the Android port's libraries

`android/fetch_deps.sh` clones these:

| project | version | licence |
|---|---|---|
| [SDL2](https://github.com/libsdl-org/SDL) | `release-2.32.10` | zlib |
| [SDL2_image](https://github.com/libsdl-org/SDL_image) | `release-2.8.8` | zlib |
| [gl4es](https://github.com/ptitSeb/gl4es) | `main` | MIT |

### `web/third_party` — empty, deliberately

The web port had exactly one third-party dependency, gl4es, and no longer has
it: the retained renderer emits a strict subset of GLES 2.0, so Emscripten's
own WebGL bindings satisfy the link with nothing in between. `web/fetch_deps.sh`
is kept as a no-op that explains itself, because the name appears in build
instructions and handoff documents and a missing file there reads like a broken
checkout. SDL2 and SDL2_image come from Emscripten's own ports (`-sUSE_SDL=2`,
`-sUSE_SDL_IMAGE=2`), which are the zlib-licensed upstreams.

The desktop build links the system SDL2 and SDL2_image.

### Not third party, despite the directory name

`web/vendor/sha256.js` is this project's own implementation of FIPS 180-4,
machine-generated by `web/vendor/gen-sha256-block.js` next to it. It is the
fallback the disc verifier uses when `crypto.subtle` is unavailable (a page
served off a plain LAN address is not a secure context). MIT, like the rest.

## Format credits

Two of the file formats decoded here were first documented by other people,
and the extractors say so at the top of the file:

* **Track geometry and textures in `static.dat`** — format credit to the
  [Burnout Modding community](https://burnout.wiki) via **EdnessP's** Noesis
  plugin `fmt_Burnout3LRD.py`. The readers here
  (`tools/py_extract_archive/extract_track.py` and `extract_textures.py`, and
  the C stages `tools/cextract/cx_track_mesh.c` and `cx_textures.c` that
  replaced them) are independent reimplementations of the Xbox path, written so
  the data can be read without Noesis.

The rest of the formats in `tools/` — `.bgv` / `.btv` vehicle meshes, `.bgd`
track data, `.awd` audio dictionaries, `.xwb` wave banks, `.txd` texture
dictionaries, the collision world, the prop tables — were reverse-engineered
here from the game's own loaders. Provenance for each is in `docs/`.
